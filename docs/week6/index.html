What I learned

Describe your design: hypervisors, tenants, VNIs and addresses. Which tenants overlap, and why did you place each VM where you did?

I use four servers, hv1 to hv4, at 10.41.0.1 to .4. IT uses VNI 100 on hv1, hv2 and hv3. BU uses VNI 200 on hv2, hv3 and hv4. Both use 10.41.100.0/24, with VMs at .10, .11 and .12. This lets me test two departments sharing servers while keeping their networks separate.

Two of your VMs have the same IP address. Using your evidence, explain how a ping reaches the right one — and what would have to go wrong for one tenant to see another's traffic.

it2 and bu2 both use 10.41.100.11. IT learns MAC 02:00:00:64:00:0b; BU learns 02:00:00:c8:00:0b. bu2 captures zero packets during IT's ping. Separate bridges and VNIs keep the traffic apart. Connecting a VM to the wrong bridge could cause a leak.

Using your evidence, explain what was flooded, to which hypervisors, and what each VTEP learned. With 50 hypervisors in one VNI, how many copies would one broadcast need — and how would EVPN change that?

it1's ARP request goes to hv2 and hv3. hv3 sees it, although the ping is to it2 on hv2. hv3 learns it1's MAC is behind hv1. hv1 learns it2's MAC is behind hv2.

With 50 servers, one broadcast needs 49 remote copies. EVPN uses BGP to share MAC locations, which reduces unknown-unicast flooding. ARP suppression can reduce ARP broadcasts. Other broadcasts can still need flooding.

Compare your two MTU fixes using your measurements. Which would you choose for a data centre, what does each cost, and who has to change what?

VXLAN adds 50 bytes. Fix A uses VM MTU 1450 and underlay MTU 1500: 1450 + 50 = 1500. It reached 4.02 Gbit/s. Ping data 1422 passed; 1423 failed. Fix B uses VM MTU 1500 and underlay MTU 9000. It reached 4.44 Gbit/s. Ping data 1472 passed; 1473 failed. These speeds can vary between runs.

I choose A to keep the underlay settings. The VM administrator must set MTU 1450, giving up 50 bytes of packet space. B keeps VM MTU 1500, but needs the network administrator to enable jumbo frames on every underlay link and check equipment support.

If your hypervisors' VTEPs were P4 switches running the lecture's vtep.p4, what would have to fill the vtep_encap table, and how? What would replace flood-and-learn?

A controller fills vtep_encap at run time, using P4Runtime. It matches the incoming VM port and destination MAC. The action sets the VNI, VTEP IPs and output details. On hv1, it2's MAC needs VNI 100 and remote VTEP 10.41.0.2. EVPN can replace flood-and-learn: BGP shares MAC locations, and the controller writes the entries.
